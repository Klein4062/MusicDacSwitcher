# 源探测机制

> 共享输出模式下 macOS 不向第三方暴露正在播放内容的真实格式，
> 这是本项目绕过该限制的核心机制。

## 流程

```
lsof -w -n -o -F pfaon（约 0.2s）
  │  只保留读句柄（'a' 字段过滤只写句柄——网易云边下边播的下载句柄
  │  offset 前进远快于播放，会把「正在播放」判定带偏）
  ▼
按扩展名筛选 + 解析文件头 → (采样率, 位深, 声道)
  ▼
间隔 1.3s 双快照比对读取偏移：
  正在播放的文件 offset 持续前进；残留句柄（列表预读/播完未关）停滞
  → 选出「正在播放」的那一首，而不是采样率最高的残留文件
```

播放器常常同时打开多个音频文件句柄，仅凭「采样率最高」会选错歌；
全部停滞时返回 nil（残留不可信），连续 3 个周期才判定源不可知。

## 支持的文件头格式

| 格式 | 识别方式 | 位深 |
|---|---|---|
| FLAC | `fLaC` + STREAMINFO bitfield | ✅ |
| WAV | RIFF/WAVE，遍历 chunk 找 `fmt ` | ✅ |
| AIFF/AIFC | FORM + COMM，80-bit extended 采样率 | ✅ |
| DSF (DSD) | `DSD ` + fmt chunk（位深记 1bit，不参与位深匹配） | — |
| M4A/MP4 | 遍历 moov→trak→mdia，音频轨（hdlr `soun`）的 mdhd timescale | nil（有损不参与） |
| 网易云 `.uc!` | 整文件单字节 XOR 0xA3 混淆 → 解出文件头后按上述格式解析（moov 在尾部时回退读文件尾） | 同内部格式 |

`.uc!` 实测（2026-11）：Hi-Res 曲目为 96k/24bit FLAC，320k 曲目为 M4A/AAC 容器，
密钥均为 0xA3。**只读取采样率/位深等元数据用于匹配输出格式，不解密、不保存音频内容。**

## 播放器支持矩阵

| 播放源 | 探测 | 行为 |
|---|---|---|
| 本地文件（FLAC/WAV/AIFF/DSF/M4A） | ✅ | 播放中即时精确匹配采样率 + 位深 |
| 网易云音乐（含 Hi-Res） | ✅ | 同上，经 `.uc!` 缓存元数据 |
| QQ 音乐 | ❌ | 缓存 `.mflac` 为 QMCv2 逐文件密钥流加密，本项目不实现解密；回退跟随设备采样率 |
| Apple Music 等流媒体 | ❌ | 无本地文件句柄；回退跟随设备采样率 |
| hog 独占播放器 | — | 完全不干预（播放器自管格式） |

回退模式（源不可知）：设备标称率变化时只优化位深（按位深策略），不改采样率。

## 边界与已知限制

- 探测每 4s 一轮（`--probe-interval`），切换发生在起播后数秒
- 多台输出设备同时播放不同内容时，文件句柄无法区分归属设备，
  探测可能跟随另一台设备正在播的文件
- 换歌间隙读取信号瞬时中断：连续 3 个周期无前进证据才判定源不可知，避免位深抖动
